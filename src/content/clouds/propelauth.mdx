## What makes PropelAuth different

PropelAuth is not a general-purpose identity provider like Auth0 or Okta; it is a specialized platform built exclusively for B2B SaaS applications. While hyperscalers and general IAM providers offer tools to build authentication from scratch or manage enterprise directory services, PropelAuth focuses on the "multi-tenant" lifecycle. It solves the complex problem of allowing end-users to sign up, create teams, invite colleagues, and manage roles without requiring the SaaS provider to build and maintain these features.

The platform provides pre-built, customizable UI components for sign-up, login, and team management that can be embedded directly into an application. This "self-service" approach allows developers to ship a production-ready onboarding flow in hours rather than weeks. It handles the intricate logic of organization membership, role inheritance, and permission checks, integrating via a simple API or SDKs for major frameworks like React, Next.js, and Node.js.

Unlike traditional cloud identity services that require significant engineering overhead to configure for B2B scenarios, PropelAuth abstracts away the infrastructure. It manages the underlying database schemas, security patches, and scalability concerns for user data. This allows engineering teams to focus on their core product logic rather than maintaining authentication infrastructure, significantly reducing time-to-market for new SaaS products.

## Pricing model

PropelAuth operates on a transparent, tiered subscription model based on the number of Monthly Active Users (MAU). This differs from usage-based cloud pricing by offering predictable costs for B2B SaaS companies.

- **Starter Plan:** Includes up to 100 MAU. This tier is designed for early-stage startups validating their product.
- **Growth Plan:** Scales with higher MAU limits (e.g., 1,000, 5,000, 10,000+ MAU tiers), unlocking advanced features like custom domains for login pages, advanced RBAC, and priority support.
- **Enterprise Plan:** Custom pricing for organizations requiring SSO (SAML), advanced security controls, and dedicated support.

The key differentiator is the inclusion of "B2B features" (team invites, role management) in the base price, whereas competitors often charge extra for these capabilities or require expensive enterprise contracts.

## When it fits

- **Early-stage B2B SaaS startups** that need to launch with full multi-tenant capabilities without hiring a dedicated security engineer.
- **Developers building internal tools or vertical SaaS** where rapid iteration on user onboarding is critical.
- **Teams migrating from home-grown auth** who want to offload the maintenance of user tables, session management, and team logic.
- **Products requiring complex role hierarchies** (e.g., Admin, Member, Viewer) that need to be managed by the end-user, not just the app owner.

## When it doesn't

- **Consumer-facing (B2C) apps** where individual user profiles and social login are the primary focus, rather than team/organization structures.
- **Enterprise identity federation** requiring deep integration with legacy on-premise Active Directory via SAML/SCIM, which is better served by Okta or Azure AD.
