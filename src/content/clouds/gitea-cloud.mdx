## What makes Gitea Cloud different

Gitea Cloud distinguishes itself by offering a single-tenant, managed Git hosting service that addresses the security and compliance concerns often associated with multi-tenant SaaS platforms like GitHub or GitLab. Unlike shared environments where data resides in a common infrastructure, Gitea Cloud provisions a dedicated, privately secured environment for each instance. This isolation ensures that customer data is not shared with other organizations, providing a higher level of assurance for industries with strict regulatory requirements.

A key architectural differentiator is that Gitea Cloud instances are deployed in the customer’s chosen cloud region (such as AWS, GCP, or Azure). This approach offers granular data residency controls, allowing organizations to store their code exactly where they want it to comply with local data sovereignty laws. The service is managed by the Gitea team, handling maintenance, backups, and scaling, which reduces the total cost of ownership compared to self-hosting while retaining the flexibility and extensibility of the open-source Gitea platform.

## When it fits

- Organizations with strict data residency requirements that need to host code within specific geographic regions or private cloud environments.
- Enterprises seeking single-tenant isolation to mitigate risks associated with multi-tenant SaaS platforms.
- Teams that want the ease of managed infrastructure (no server maintenance) but prefer the open-source Gitea ecosystem over proprietary alternatives.
- Startups and small teams looking for cost-effective, all-in-one Git and CI/CD solutions with potential startup discounts.

## When it doesn't

- Teams requiring a vast array of native cloud services (such as serverless functions, managed databases, or AI/ML tools) beyond source control and CI/CD.
- Users who need a purely multi-tenant, low-cost solution for open-source projects without the need for private isolation or dedicated infrastructure.
